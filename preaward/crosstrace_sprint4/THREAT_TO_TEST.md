# Development threat-to-test traceability

This table links the current local threat model to deterministic engineering
checks. It is a review aid, not evidence of attack frequency, safety benefit,
or production security. The Sprint 4 cases are hand-written fixtures and are
permanently excluded from later calibration and confirmation.

| Threat or boundary | Mechanism exercised | Development check | Sprint 4 case | What remains unproved |
|---|---|---|---|---|
| Altered, malformed, or non-canonical evidence | Strict decoding, derived identifiers, and signatures | `tests/test_delivery.py::test_raw_message_decoder_requires_canonical_unique_key_json`; `tests/test_sprint2_evidence.py::test_mutation_invalid_signature_unknown_key_and_unknown_store_are_rejected` | None | Correctness of every future wire format and parser |
| Missing receiver-held evidence | Both endpoint records are required for `SL` and `CR`; one complete `PR` copy contains both attestations | `tests/test_sprint2_evidence.py::test_endpoint_representation_requires_both_endpoint_records`; `tests/test_sprint4_harness.py::test_one_retained_receipt_copy_is_the_only_intended_representation_difference` | `one-leaf-receiver-locally-withheld` | Real copy-loss rates or an availability advantage |
| Missing all local leaf evidence | The gate cannot construct an action leaf and pauses | `tests/test_sprint4_harness.py::test_status_scope_conflict_and_missing_evidence_branches` | `both-leaf-copies-locally-withheld` | Availability during a real partition |
| Delay, loss, reordering, or directional partition | Delivery is fixed by neutral slots; the local view exposes only evidence delivered by its cutoff | `tests/test_delivery.py::test_schedule_is_reproducible_and_input_order_independent`; `tests/test_delivery.py::test_directional_partition_buffers_until_exact_healing_time`; `tests/test_delivery.py::test_projection_hides_future_loss_withholding_other_stores_and_schedule_state` | `status-delayed-locally-audit-visible` | A representative network distribution or acceptable pause rate |
| Wrong parent, broken party continuity, or impossible causal time | Representation validators and the common chain require an exact delivered parent and ordered hand-off | `tests/test_sprint2_evidence.py::test_endpoint_child_requires_delivered_parent_and_party_continuity`; `tests/test_sprint3_common_gate.py::test_parent_party_and_causal_failures_never_reach_common_policy` | None | Correct behaviour for every future topology |
| Receiver rejection or mismatched cross-reference | An authenticated rejection remains auditable but cannot enter an allowed chain | `tests/test_sprint2_evidence.py::test_authenticated_rejection_is_retained_but_never_allowed`; `tests/test_sprint2_evidence.py::test_mismatched_handoff_and_wrong_cross_reference_fail_closed` | None | Truth or wisdom of the receiver's decision |
| Authenticated equivocation or sender-sequence reuse | Conflicting records poison the interaction instead of being selected by input order | `tests/test_sprint2_evidence.py::test_conflicting_authenticated_records_are_not_selected_by_sort_order`; `tests/test_sprint2_evidence.py::test_sender_sequence_equivocation_across_interaction_ids_fails_closed` | `authenticated-conflicting-leaf` | Detection when conflicting views never meet |
| Invalid status signature or untrusted origin store | Every delivered status is authenticated against a role-scoped key and configured status store | `tests/test_sprint3_common_gate.py::test_invalid_status_signature_and_origin_store_pause_during_preparation` | None | Correctness of the configured registry or network-origin authentication |
| Missing, future, stale, revoked, or conflicting authority status | Any delivered same-version conflict pauses; otherwise the highest delivered version controls | `tests/test_sprint3_common_gate.py::test_revoked_and_stale_statuses_pause`; `tests/test_sprint3_common_gate.py::test_same_version_status_conflict_never_selects_active_candidate`; `tests/test_sprint3_common_gate.py::test_missing_and_future_authority_statuses_pause` | `status-delayed-locally-audit-visible`; `higher-revocation` | Knowledge of a newer status that was not delivered |
| Authority-lineage, role, or scope expansion | Root authority, one lineage/version, attenuation, and current time bounds are required | `tests/test_sprint3_common_gate.py::test_lineage_root_role_and_scope_time_fail_closed`; `tests/test_sprint3_common_gate.py::test_scope_expansion_action_out_of_scope_and_action_hash_change_pause` | `out-of-scope` | Cumulative budgets or legal authority |
| Action substitution after signing | The leaf request hash and every scope must match the exact structured action | `tests/test_sprint3_common_gate.py::test_scope_expansion_action_out_of_scope_and_action_hash_change_pause` | `out-of-scope` | Safety or desirability of an otherwise in-scope action |
| Replay, stale state, or competing reservation | One neutral replay key spans `SL`, `CR`, and `PR`; reservation compares the store revision atomically | `tests/test_sprint3_common_gate.py::test_cross_representation_replay_is_one_neutral_replay_key`; `tests/test_sprint3_common_gate.py::test_stale_revision_and_concurrent_reservation_fail_closed`; `tests/test_sprint4_harness.py::test_replay_consumes_once_then_pauses_without_second_adapter_call` | `replay` | Replay at another verifier or after state loss |
| Conflicting stored interaction or sender sequence | Observation bindings and permit reservation share one transaction | `tests/test_sprint3_common_gate.py::test_stored_neutral_interaction_conflict_rolls_back_gate_reservation`; `tests/test_sprint3_common_gate.py::test_deterministic_id_collision_rolls_back_observations_and_revision` | None | A distributed conflict registry |
| Crash after an adapter attempt | Permit state changes to `ATTEMPTED` before the adapter call and is never automatically retried | `tests/test_sprint3_common_gate.py::test_consume_mismatches_expiry_and_attempted_crash_do_not_retry`; `tests/test_sprint3_common_gate.py::test_consume_before_adapter_finish_and_replay` | `replay` | Automatic reconciliation or exactly-once execution |
| Caller-authored policy input or evaluator metadata leak | Only process-tagged prepared inputs authorize; common input omits representation, case, oracle, and schedule fields | `tests/test_sprint3_common_gate.py::test_deserialized_input_unknown_tool_and_string_registries_are_rejected`; `tests/test_sprint4_harness.py::test_common_gate_input_has_no_evaluator_or_representation_labels` | All gate cases | Protection from arbitrary code in the same process |
| Gate bypass in the audit control | Audit cells never construct the gate or mutate permit state | `tests/test_sprint4_harness.py::test_pause_never_reaches_adapter_and_audit_never_mutates_permits` | All audit cells | Calls through an uninstrumented real tool |
| Result or source tampering | Exact source closure, checksums, internal identifiers, recomputation, and deterministic regeneration | `tests/test_sprint4_harness.py::test_release_verifies_and_regenerates`; `tests/test_sprint4_harness.py::test_tampering_fails_even_after_checksums_are_rewritten`; `tests/test_sprint4_harness.py::test_source_closure_is_explicit_and_contains_no_user_files` | Release-wide | Trust in the tagged commit, host, dependencies, or build platform |
| Collusion, shared or stolen keys, clones, global forks, cumulative budgets, and out-of-band actions | No in-scope prevention claim | Documented limitation in `THREAT_MODEL.md`, `preaward/DEVELOPMENT_CLAIMS_BOUNDARY.md`, and the Sprint 3 README | None | Entirely outside this development release |

For the exact six-cell construction and safe interpretation, see
`preaward/REVIEWER_REPRODUCTION.md` and
`preaward/DEVELOPMENT_CLAIMS_BOUNDARY.md`.
