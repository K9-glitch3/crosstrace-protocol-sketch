# Claims boundary for pilot v0.1

## Supported if the release verifies

- The published 300-execution scripted matrix ran without model or network calls.
- The scorer used one hashed oracle per case across all five conditions.
- Given a complete receipt chain and the declared current signed status, the
  present local gate reproduced the declared valid, revocation-update, limit,
  and replay counterfactuals.
- Isolated local stores reproduced the documented fork limitation, and a joined
  local view detected the conflict after both simulated actions had executed.
- The result files can be checksum-verified and the summary recomputed.

## Not supported

- CrossTrace makes AI systems safer.
- Paired receipts outperform isolated signed logs in real deployments.
- The fixture variants are independent trials or support statistical inference.
- The harness represents frontier models or independently operated organisations.
- A local gate prevents equivocation when conflicting views have not merged.
- The P0 run tests evidence delivery, revocation propagation, latency, or
  decision-time partial observability.
- Signatures make statements true, prevent collusion, or distinguish clones
  sharing one key.
- The mechanism provides global replay protection, cumulative budget control,
  or coverage of uninstrumented tools.

The honest description for an application is: “a deterministic, credential-free
systems pilot that exercises the current mechanism and publishes its local fork
failure; no model-level outcome results yet.”
